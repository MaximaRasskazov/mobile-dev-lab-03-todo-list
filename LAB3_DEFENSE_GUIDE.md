# ЛР3. Памятка для защиты

## О чём лабораторная

Приложение хранит список задач. Можно добавить задачу, изменить её название, удалить, отметить выполненной, найти по части названия и выбрать фильтр. У каждой задачи отображается дата создания. Дополнительные возможности из ТЗ — сортировка (сначала новые, сначала старые, по названию) и локальное сохранение задач между запусками.

Использованы стандартные средства Flutter: StatefulWidget, setState, Form и Navigator. Для локального хранения подключён пакет shared_preferences. Используется его современный класс SharedPreferencesAsync; на вебе он работает через localStorage, на Android — через DataStore Preferences. В pubspec.yaml также остались стандартные зависимости шаблона Flutter; cupertino_icons в нашем коде не используется.

## Структура проекта

```text
lib/
  main.dart                         запуск и тема приложения
  models/todo.dart                  данные одной задачи
  repositories/todo_repository.dart список задач, операции CRUD, чтение и запись хранилища
  pages/todo_screen.dart            список, поиск, фильтры, сортировка
  pages/todo_form_page.dart         форма добавления и редактирования
test/widget_test.dart              автоматические проверки сценариев
```

В `todo_screen.dart` находятся `TodoScreen` и `TodoState`. Это соответствует схеме из ТЗ: TodoScreen → TodoState → TodoRepository. Отдельный класс управления состоянием не нужен: TodoState уже является State главного экрана.

Папки android, ios, web, windows, macos, linux создал Flutter. Это платформенные оболочки. Для объяснения логики лабораторной начни с lib, а не с этих папок.

## Как работает приложение

1. `main()` вызывает `runApp(const TodoApp())`.
2. `TodoApp` создаёт `MaterialApp`, который открывает `TodoScreen`.
3. `TodoState` создаёт один `TodoRepository`. В initState вызывается loadTodos: пока хранилище читается, показывается индикатор загрузки; после чтения появляются сохранённые задачи.
4. Кнопка `+` вызывает `openForm(null)`.
5. `Navigator.push<String>` открывает `TodoFormPage`. Главный экран ждёт результат через `await`.
6. Пользователь вводит название. `saveTodo()` проверяет форму.
7. При правильном вводе `Navigator.pop(context, название)` закрывает форму и возвращает строку.
8. Главный экран вызывает `repository.addTodo(title)` внутри `setState`, затем ждёт `saveTodos()`, который записывает обновлённый список в хранилище.
9. Flutter снова вызывает `build`. Метод `getVisibleTodos()` получает подходящие задачи, сортирует их, и экран показывает карточки.

При редактировании в `openForm` передаётся существующий объект Todo. Форма копирует его название в контроллер. До нажатия «Сохранить» объект не изменяется, поэтому «Отмена» и стрелка назад сохраняют прежние данные.

## Модель и хранение

`Todo` — обычный класс с тремя полями:

- `String title`: название, его можно менять.
- `bool isDone`: выполнена ли задача, изначально false.
- `final DateTime createdAt`: момент создания, его не меняем при редактировании.

`TodoRepository` хранит `List<Todo> _todos`. Подчёркивание делает поле приватным для Dart-библиотеки, то есть здесь для файла repository.

Во время работы задачи находятся в памяти в `_todos`. После добавления, редактирования, удаления или переключения выполнения весь список записывается в локальное хранилище. При следующем запуске он читается обратно. Сохраняются название, isDone и исходная дата createdAt. Поисковый запрос, фильтр и выбранный режим сортировки между запусками сбрасываются.

Путь сохранения: Todo → toJson() → список Map → jsonEncode → строка → preferences.setString('todo_list', строка).

Путь загрузки: preferences.getString('todo_list') → jsonDecode → список данных → Todo.fromJson() → список Todo.

JSON — текстовый формат для хранения данных. Наш объект Todo напрямую записать нельзя, поэтому сначала превращаем его в Map с полями title, isDone, createdAt. DateTime превращается в ISO-строку через toIso8601String, а при чтении восстанавливается DateTime.parse.

SharedPreferencesAsync выбирает хранилище по платформе: в браузере — localStorage, на Android — DataStore Preferences. Данные локальные: между телефоном и браузером не синхронизируются. В браузере нужно открывать тот же адрес и порт в том же профиле. Очистка данных сайта или удаление данных приложения уберёт задачи.

Для сохранения при веб-разработке удобно каждый раз запускать один и тот же адрес:

```powershell
flutter run -d web-server --web-port 8752 --web-hostname 127.0.0.1
```

`loadTodos()` сначала собирает временный список loadedTodos и только после успешного чтения всех элементов заменяет `_todos`. Если данные повреждены или хранилище недоступно, экран показывает ошибку и «Повторить». Создавать новые задачи на этом экране нельзя: это защищает прежнюю запись от случайной замены пустым списком.

Если запись не удалась, изменение остаётся в памяти, а SnackBar предлагает «Повторить». До успешной записи такое изменение может потеряться при закрытии приложения. Флаг isSaving не позволяет запускать изменения списка одновременно с текущей записью.

`getTodos()` возвращает новый список, но сами задачи внутри него остаются теми же объектами. Поэтому сортировка копии не меняет порядок хранения, а изменение `todo.title` меняет нужную задачу. Это поверхностная копия, не полная копия всех объектов.

## CRUD: что показать в коде

| Операция | Метод TodoRepository | Действие пользователя |
| --- | --- | --- |
| Create — создание | addTodo | Нажать +, заполнить форму, сохранить |
| Read — чтение | getTodos | Открыть главный экран |
| Update — изменение | updateTodo, toggleTodo | Изменить название или нажать флажок |
| Delete — удаление | deleteTodo | Открыть меню карточки и выбрать «Удалить» |

Название не является идентификатором. В методы передаётся сам объект Todo. Две задачи с одинаковым названием допустимы; удаление одной не удаляет вторую.

## Формы и валидация

Файл: `lib/pages/todo_form_page.dart`.

`Form` объединяет поля формы. `GlobalKey<FormState>` даёт доступ к состоянию этой формы. Ключ создаётся один раз в State, а не заново при каждом build.

`TextFormField` — поле ввода, которое умеет показывать ошибку от validator. Обычный `TextField` используется для поиска, где сохранение и проверка формы не нужны.

`TextEditingController` позволяет прочитать введённый текст и заранее подставить название при редактировании. В `initState()` подставляется исходный текст, а в `dispose()` освобождается контроллер.

`validator` возвращает сообщение об ошибке, если значение равно null или после `trim()` пустое. Если ошибок нет, возвращает null. `trim()` убирает пробелы в начале и конце, поэтому название из одних пробелов не пройдёт проверку.

В `saveTodo()` вызывается `formKey.currentState!.validate()`. Только при результате true выполняется возврат названия. Проверка действует и при добавлении, и при редактировании.

Знак `!` здесь означает: мы уверены, что состояние формы уже существует, поскольку кнопку нажимают на построенном экране. Это не тот же случай, что `!todo.isDone`: перед bool знак `!` меняет true на false и наоборот.

## Навигация

Route — маршрут, представляющий открываемый экран приложения. `MaterialPageRoute` создаёт маршрут формы и стандартный переход к нему.

`Navigator` управляет стеком маршрутов: новый экран кладётся поверх предыдущего. `Navigator.push` открывает форму. `Navigator.pop` закрывает верхний экран; необязательный второй аргумент возвращает результат предыдущему экрану.

В `openForm()` тип `<String>` означает, что от формы ожидается строка. При возврате без сохранения результат равен null. Метод объявлен `Future<void>` и `async`, потому что внутри ждёт результат через `await`; блокировки всего приложения при этом нет.

После ожидания проверяется `mounted`: существует ли ещё State главного экрана. Если экран уже закрыт, вызывать его setState нельзя.

## Состояние

`StatefulWidget` — описание виджета, у которого есть изменяемое состояние. `State` хранит эти данные и строит интерфейс через build. В этой работе `TodoState` хранит repository, поисковый текст, выбранный фильтр, сортировку и флаги загрузки/сохранения.

`setState(() { ... })` выполняет изменение и сообщает Flutter, что интерфейс нужно перестроить. Например, при нажатии флажка сначала меняется isDone, затем карточка рисуется с новым значением Checkbox и зачёркнутым названием.

TodoRepository не вызывает setState: его задача — операции с данными. Экран отвечает за обновление интерфейса. Репозиторий создаётся полем State, а не внутри build, поэтому список не пропадает при каждом перестроении.

## Поиск и фильтрация

Файл: `lib/pages/todo_screen.dart`, метод `getVisibleTodos()`.

1. Создаём пустой результирующий список.
2. Убираем крайние пробелы из запроса и приводим его к нижнему регистру.
3. Циклом for перебираем задачи репозитория.
4. Если выбран фильтр «Активные», пропускаем выполненные задачи.
5. Если выбраны «Выполненные», пропускаем активные задачи.
6. Если название не содержит запрос, пропускаем задачу.
7. Остальные добавляем в результат.
8. Сортируем результат и возвращаем его для отображения.

`continue` пропускает оставшуюся часть текущего прохода цикла и переходит к следующей задаче. `contains` проверяет вхождение подстроки. Пустая строка входит в любое название, поэтому пустой поиск показывает все задачи выбранного фильтра.

Поиск не зависит от регистра: «ХЛЕ» находит «Купить хлеб». Поиск, фильтр и сортировка работают одновременно. Они не удаляют задачи из репозитория.

## Дополнительное задание: сортировка

Сортировка была выбрана первой. По отдельной просьбе добавлено ещё одно задание из раздела 9 ТЗ — локальное сохранение; оно описано в разделе «Модель и хранение».

В выпадающем списке три значения:

- «Сначала новые»: сравниваем дату второй задачи с датой первой.
- «Сначала старые»: сравниваем дату первой с датой второй.
- «По названию»: сравниваем названия, приведённые к нижнему регистру.

`List.sort` получает функцию сравнения двух элементов. Отрицательный результат ставит первый элемент раньше второго, положительный — позже, ноль означает равенство по выбранному признаку.

`compareTo` выполняет само сравнение. Для дат это хронологический порядок. Для строк — порядок символов после приведения к нижнему регистру, без специальных правил русского словаря для «ё» и смешанных алфавитов. Отдельного дополнительного порядка для одинаковых названий или дат нет.

При изменении названия сортировка пересчитывается, поэтому карточка может переместиться. При редактировании дата создания сохраняется.

## Официальные контрольные вопросы

### Что такое CRUD?

Create, Read, Update, Delete — создание, чтение, изменение и удаление данных. В нашей работе это добавление задачи, вывод списка, изменение названия или статуса и удаление. Все четыре операции можно показать в `TodoRepository`.

### Как валидировать форму?

Нужно использовать Form с ключом GlobalKey<FormState> и добавить validator в TextFormField. При сохранении вызываем validate; если хотя бы одно поле вернуло ошибку, не сохраняем. В `saveTodo()` проверяется название после удаления крайних пробелов.

### Что такое route?

Это маршрут, через который Navigator представляет открытый экран. В нашем приложении MaterialPageRoute открывает TodoFormPage. push добавляет маршрут, pop закрывает его и при сохранении возвращает название задачи.

### Где лучше хранить состояние списка?

Его следует хранить там, где оно сохраняется между перестроениями и доступно нужным действиям. В этой работе TodoState держит единственный TodoRepository со списком и параметры отображения; изменения оборачиваются в setState. Создавать новый репозиторий внутри build нельзя: тогда данные терялись бы при перестроениях.

## Возможные вопросы преподавателя

1. **Почему StatefulWidget?** Задачи, поиск, фильтр и сортировка меняются во время работы.
2. **Что делает setState?** Сообщает Flutter, что нужно заново построить интерфейс после изменения данных.
3. **Где хранится список?** В поле `_todos` объекта TodoRepository.
4. **Зачем repository?** Чтобы операции с данными были отделены от кнопок и других виджетов.
5. **Что будет после закрытия приложения?** После нового запуска сохранённые задачи загрузятся из локального хранилища.
6. **Где Create?** В addTodo: создаётся Todo и добавляется в список.
7. **Где Read?** В getTodos, затем getVisibleTodos и build показывают задачи.
8. **Где Update?** В updateTodo и toggleTodo.
9. **Где Delete?** В deleteTodo через remove.
10. **Почему нельзя сохранить пробелы?** validator применяет trim и проверяет isEmpty.
11. **Что возвращает validator при успехе?** null.
12. **Зачем TextEditingController?** Прочитать ввод и подставить название при редактировании.
13. **Зачем dispose?** Освободить контроллер после удаления формы из дерева виджетов.
14. **Чем TextField отличается от TextFormField?** TextFormField связан с Form и поддерживает validator.
15. **Что делает push?** Открывает новый маршрут и позволяет дождаться результата.
16. **Что делает pop?** Закрывает текущий маршрут и может вернуть результат.
17. **Как определяется режим формы?** Если todo равен null — добавление, иначе редактирование.
18. **Что вернётся при отмене?** null, поэтому главный экран ничего не изменит.
19. **Как работает поиск?** Название и запрос приводятся к нижнему регистру, затем проверяется contains.
20. **Почему после переключения фильтра задача не удаляется?** Меняется только результирующий список, репозиторий сохраняет все задачи.
21. **Как видно выполнение?** Установлен Checkbox, название серое и зачёркнутое.
22. **Почему getTodos возвращает копию?** Чтобы операции с порядком внешнего списка не меняли порядок хранения.
23. **Почему final List можно пополнять?** final запрещает заменить ссылку, но не запрещает менять содержимое списка.
24. **Что означает Todo?** Переменная может содержать Todo или null.
25. **Зачем mounted после await?** За время ожидания экран мог закрыться, и тогда setState вызывать нельзя.
26. **Как сортируются задачи?** Через sort и compareTo по названию или createdAt.
27. **Дата меняется при редактировании?** Нет, createdAt является final и присваивается при создании.
28. **Что при одинаковых названиях?** Хранятся разные объекты Todo; работа ведётся с выбранным объектом.
29. **Как решён узкий экран?** Фильтры переносятся через Wrap, список и форма прокручиваются, длинное название ограничено двумя строками.
30. **Почему нет Provider или базы данных?** Для обновления интерфейса достаточно setState. Небольшой список сохраняется строкой JSON через shared_preferences; отдельная база данных не нужна.

### Сценарий ручной демонстрации

1. Запусти приложение. Добавь «Купить хлеб» и «Сделать лабораторную».
2. Попробуй сохранить пустое название, затем несколько пробелов: должна появиться ошибка.
3. Нажми карточку «Купить хлеб», поменяй название на «Купить молоко» и сохрани.
4. Отметь задачу выполненной: флажок установлен, название зачёркнуто.
5. Выбери «Активные», «Выполненные», «Все» и покажи изменение списка.
6. Введи «МОЛ»: должна найтись задача «Купить молоко». Очисти поиск.
7. Переключи три режима сортировки; для наглядного порядка по дате добавляй задачи с небольшой паузой.
8. Через меню карточки удали одну задачу.
9. Открой редактирование оставшейся, измени ввод и нажми «Отмена»: название должно остаться прежним.
10. Полностью перезапусти приложение или обнови веб-страницу на том же адресе: оставшаяся задача, дата и статус должны восстановиться. Затем покажи код Todo, TodoRepository, getVisibleTodos и validator.

## Рассказ на 30 секунд

Я сделал приложение «Список задач» на Flutter. Во время работы задачи хранятся в репозитории, а после изменений сохраняются локально через shared_preferences. Можно добавлять, редактировать и удалять задачи, отмечать выполнение, искать по названию и применять фильтры. Для обновления интерфейса использую StatefulWidget и setState. Форма проверяет название через validator, а переходы между экранами сделаны через Navigator. Реализованы сортировка по названию и дате создания, а также локальное сохранение. После полного перезапуска сохранённые задачи восстанавливаются.

## Самое главное перед защитой

- Todo — одна задача, List<Todo> — список задач.
- Repository — хранение и операции с данными.
- JSON — текстовая запись полей задачи; shared_preferences сохраняет эту строку между запусками.
- State — изменяемые данные экрана, setState — запрос на перестроение.
- CRUD — создать, прочитать, изменить, удалить.
- Form + validator — проверка полей перед сохранением.
- push — открыть экран, pop — вернуться с результатом или без него.
- Поиск и фильтры строят отдельный список, сортировка меняет его порядок.
- Все новые конструкции в приложении можно найти в пяти файлах lib.
