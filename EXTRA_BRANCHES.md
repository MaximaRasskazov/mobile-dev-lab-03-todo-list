# Ветки с дополнительными заданиями

`main` — основная версия: сортировка, локальное сохранение и тёмно-синий фон `#0B1628`. Расположение элементов остаётся стандартным Flutter; тёмная палитра обеспечивает читаемость текста на фоне.

Остальные ветки созданы независимо от main, каждая добавляет одну возможность:

| Ветка | Дополнительное задание | Как показать |
| --- | --- | --- |
| extra/priority | Приоритет | Выбрать низкий, обычный или высокий приоритет в форме |
| extra/categories | Категории | Выбрать категорию в форме и увидеть её в карточке |
| extra/due-date | Срок выполнения | Выбрать дату в календаре; изменить или убрать срок |
| extra/reorder | Перетаскивание задач | Выбрать сортировку «Вручную» и потянуть задачу за значок справа |

Все ветки сохраняют возможности основной версии, включая локальное хранение. Их не нужно сливать между собой для демонстрации: переключайся на нужную.

## Как переключаться

Сначала останови `flutter run` клавишей `q`. Убедись через `git status`, что у тебя нет несохранённых изменений, затем:

```powershell
git switch extra/priority
flutter pub get
flutter run
```

Вместо extra/priority можно указать любую ветку из таблицы. Вернуться к основной:

```powershell
git switch main
```

После смены ветки нужен полный перезапуск приложения. Для браузера используй тот же адрес и порт:

```powershell
flutter run -d web-server --web-port 8752 --web-hostname 127.0.0.1
```

## Данные разных вариантов

У каждой дополнительной ветки отдельный ключ хранилища. При первом запуске, если её собственной записи ещё нет, она читает задачи main как исходный список. Затем изменения сохраняются только под ключом своей ветки. Это позволяет демонстрировать варианты, не меняя задачи основной версии.

## Коммиты и публикация

Новые изменения сохраняются отдельным коммитом для каждого файла. Существующая история не переписывается. Push выполняет владелец проекта самостоятельно.

В каждой дополнительной ветке есть файл EXTRA_TASK.md с объяснением её кода, новых конструкций и сценарием проверки.
